# 10. План работ, риски и открытые вопросы

## 1. Этапы

Оценка — для одного опытного Go-разработчика, знакомого с репозиторием, при неизменных
требованиях. В скобках — календарь при неполной занятости (~3 дня в неделю).

Решения владельца уже зафиксированы: WASM не нужен; доступ через nginx/443 на
поддомене `torrentino.example.com` (`base-path: "/"`); путь `/torrentino` —
только временный редирект; несколько равноправных аккаунтов; удаление сразу, как в
Telegram; английский UI.

| Этап | Содержание | Оценка |
|---|---|---|
| **M0. Согласование проекта** | ревью этого каталога, фиксация решений | 0,5–1 д |
| **M1. Phase 0: фундамент** | `common/list` (`View`, перенос `List`), `core` (модели, действия, сервисы, интерфейсы), контексты/таймауты в `api/*`, перевод Telegram-хендлеров на `core`, SIGTERM/graceful shutdown | 4–6 д |
| **M2. Каркас web** | `web`-сервер, конфиг/валидация, `base-path`/URL helper, логин, несколько аккаунтов, сессии, CSRF, middleware, шаблоны/layout, `{base}/healthz`, `-hash-password` | 5–6 д |
| **M3. Паритет экранов** | `/find` (+ lazy hash, actions, torrent stream), `/downloads` (+ disk, footer, poll, immediate delete, выбор по ключу), `/torrserver`, команды, фрагменты, ошибки | 7–10 д |
| **M4. Безопасность, nginx и эксплуатация** | rate limit, аудит, заголовки/CSP, nginx-конфиг и TLS, документация (readme/AGENTS/ops), регрессия Telegram, нагрузочные проверки | 4–6 д |
| **M5. Приёмка** | деплой за nginx, учения «Telegram недоступен», чеклист паритета, исправления | 1–2 д |

Итого v1: **22–31 день** (~5–6 недель при неполной занятости).

Порядок обязателен: M1 → M2 → M3; M4 идёт параллельно M3 там, где не конфликтует.
`base-path` и nginx-конфиг нужны уже в M2/M3, иначе тестирование пойдёт не в том URL.

## 2. Зависимости и точки принятия решений

- **M1 — жёсткая зависимость.** Без вынесенных `core`/`list.View` M3 начнёт дублировать
  логику, и паритет будет недостижим без переписывания.
- **M2/M3 — после M1.** Параллельно можно готовить шаблоны/статику и nginx-конфиг,
  но не обработчики.
- **nginx/TLS — до приёмки.** Локально можно разрабатывать с `base-path: "/"` и
  `listen: 127.0.0.1:8088`; финальная проверка — на поддомене под 443, со старым путём
  как редиректом.
- **Security review — до M5**, по чеклисту 06, §14.
- **WASM — вне плана** (решение согласовано); пересматривать только при триггерах из
  07, §6.

## 3. Риски

| # | Риск | Вероятность | Влияние | Меры |
|---|---|---|---|---|
| R1 | Рефакторинг M1 ломает Telegram | средняя | высокое | поведение-сохраняющий перенос, существующие тесты, golden-тесты `View`, smoke после каждого шага |
| R2 | XSS через названия/ссылки трекеров | средняя | высокое | `html/template`, запрет `template.HTML`, CSP, security-тесты |
| R3 | Случайное удаление файлов (нет подтверждения) | средняя | высокое | паритет с Telegram; выбор по стабильному ключу, CSRF+Origin, проверка путей, аудит, красная кнопка; в будущем read-only роль/корзина |
| R4 | 60-секундный поиск упирается в таймауты сервера/прокси | высокая | среднее | PRG, `WriteTimeout` 90 с, `proxy_read_timeout 120s`, индикатор прогресса, отмена по контексту |
| R5 | Обход диска на каждом опросе | средняя | среднее | кэш снимка 2 с, обход вне lock, лимит глубины |
| R6 | Веб умирает вместе с процессом бота | низкая | среднее | systemd `Restart=always`; при необходимости — отдельный процесс в будущем |
| R7 | Потеря сессий при рестарте | высокая | низкое | документировано; повторный вход |
| R8 | Подбор пароля / перехват | средняя | высокое | PBKDF2, rate limit, TLS на nginx, `Secure` cookie, HSTS |
| R9 | DoS сессиями/логином | низкая | среднее | лимит 512 сессий, GC, rate limit |
| R10 | htmx сломает CSP или обновится несовместимо | низкая | низкое | фиксированная версия, `allowEval=false`, CSP-тест |
| R11 | Глобальное состояние Telegram остаётся | высокая (существующее) | низкое для web | web не использует `paginator.Handlers`; Telegram-дефект вне scope |
| R12 | Расползание объёма (роли, SPA, настройки в UI) | высокая | среднее | non-goals из 01, отдельные решения на будущее |
| R13 | Зависание скрейпинга постера / `.torrent` | средняя | среднее | контекст+таймауты+лимиты в M1 |
| R14 | Несовпадение таймаутов прокси и поиска | средняя | среднее | примеры конфигов, диагностика в 08 |
| R15 | Удаление файла вне разрешённых корней | низкая | высокое | проверка `filepath.Clean` + префикс `path.*`, тесты |
| R16 | Возврат к path-fallback `/torrentino` | низкая | высокое | основной вариант — поддомен; fallback возвращает same-origin риск (06, T15) |
| R17 | Ошибки `base-path` в fallback: ссылки/редиректы/cookie вне префикса | низкая | среднее | `url()` helper, тесты на `/` и `/torrentino`, проверка `Path` cookie |
| R18 | Ошибки nginx поддомена: `server_name`, сертификат, `proxy_pass` | средняя | высокое | конфиг из 08, диагностика SNI/сертификата, `nginx -T` |
| R19 | Неверный `secure-cookies`/`X-Forwarded-Proto` | средняя | среднее | `trusted-proxies`, тест Set-Cookie, диагностика |

## 4. Решения и открытые вопросы

| # | Вопрос | Ответ |
|---|---|---|
| Q1 | Пользователи и роли | **решено:** несколько равноправных аккаунтов, без ролей в v1 |
| Q2 | Доступ | **решено:** интернет/домен, nginx 443, поддомен `torrentino.example.com`, TLS на nginx; путь `/torrentino` — только редирект |
| Q3 | WASM | **решено:** не нужен в v1 |
| Q4 | Подтверждение удаления | **решено:** удаление сразу, как в Telegram |
| Q5 | Язык UI | **решено:** английский, как в боте |
| Q6 | Плеер Torrserver в нашем UI | нет (вне паритета) |
| Q7 | Сохранять сессии после рестарта? | нет (in-memory) |
| Q8 | Несколько вкладок одного экрана? | одна сессия/экран на тип; per-tab — позже |
| Q9 | Ограничивать число результатов поиска? | нет в v1; `web.max-results`, если память станет проблемой |
| Q10 | История действий в UI? | нет, только аудит в лог |

## 5. Что явно не делаем в этом проекте

- не чиним Telegram ACL для callback-ов (AGENTS.md п. 13) — отдельная задача;
- не чиним глобальный `downloads.Updater` (один на процесс) — отдельная задача;
- не переносим `transmissionrpc` на v3 и не выносим креденшелы Transmission в конфиг;
- не делаем настройки в UI, регистрацию, восстановление пароля, 2FA;
- не делаем мобильное приложение/PWA;
- не добавляем JSON API до появления реального клиента;
- не оставляем путь `/torrentino` как второй постоянный вход: только временный редирект.

## 6. Будущее (после v1)

1. Read-only роль для веб-аккаунтов.
2. Убрать старый путь `/torrentino` и fallback-режим `base-path` после миграции
   (оставить поддержку только `/`).
3. Изоляция вкладок (per-tab screen ID).
4. SSE вместо опроса для мгновенных обновлений.
5. JSON API + SPA/WASM-клиент (см. 07), если появятся триггеры.
6. PWA-оболочка.
7. Локализация (RU/EN) и переключатель темы.
8. Просмотр Torrserver-плеера/ссылки на него из списка.
9. Метрики Prometheus (`{base}/metrics` за авторизацией) и алерты.
10. Исправление Telegram ACL для callback-ов и глобального состояния — заодно улучшит
    многопользовательский сценарий в Telegram.
11. Мягкое удаление (корзина) вместо необратимого `os.Remove`.

## 7. Вехи и критерии выхода

| Веха | Критерий |
|---|---|
| M1 | Telegram работает как до рефакторинга; `go test -race ./...`; `core`/`list` покрыты тестами; `api/*` принимают контекст |
| M2 | логин/логаут/сессии/CSRF работают; `{base}/healthz`; каркас страниц; конфиг валидируется; cookie с `Path={base}` |
| M3 | все три экрана и действия доступны в браузере на поддомене (base `/`); матрица 02 закрыта, кроме отступлений |
| M4 | security-чеклист 06, §14; аудит; rate limit; nginx-конфиг проверен; документация 08 обновлена; регрессия Telegram |
| M5 | деплой за nginx/443; учения 09, §8; критерии приёмки 09; демо владельцу |

## 8. Календарный ориентир (неполная занятость)

```
неделя 1   M0 + начало M1
неделя 2   M1, старт M2
неделя 3   M2 (base-path, auth), старт M3
неделя 4   M3
неделя 5   M3 завершение + M4 (nginx/security)
неделя 6   M5, демо
```

При полной занятости — примерно 4–5 недель. Решения Q1–Q5 уже приняты, поэтому
пересмотр требований не должен растягивать срок.
