# 01. Цели и границы

## 1. Контекст

`torrentino` — один Go-бинарник, который сейчас целиком является Telegram-ботом:

- `main.go` загружает `settings.json`, создаёт `bot.Bot`, регистрирует ACL-middleware и
  три обработчика: поиск (default handler), `/downloads`, `/torrserver`;
- UI строится вокруг `common/paginator`: сообщение + inline-клавиатура, страницы по 4
  элемента, сортировки, фильтры, действия;
- доменная логика размазана по `handlers/*` и `api/*`: `handlers/search` сам вызывает
  Jackett, Transmission и Torrserver, `handlers/downloads` читает диск и `statfs`,
  `handlers/torrserver` дергает Torrserver;
- состояние экранов глобальное: `paginator.Handlers` хранит один handler на префикс,
  а сам `Paginator` живёт в замыкании обработчика.

Telegram здесь — не транспорт для бизнес-логики, а единственный рендерер и единственный
источник идентичности пользователя (`users-list` с Telegram ID).

## 2. Проблема

Если Telegram недоступен, бот продолжает работать, но управлять им нельзя. При этом
Jackett, Transmission и Torrserver доступны, а на NAS есть свободный HTTP-порт.
Telegram-зависимость UI — единственная точка отказа, которую можно убрать, не трогая
внешние сервисы.

## 3. Сценарии

| # | Сценарий | Ожидание |
|---|---|---|
| S1 | Telegram API недоступен (сбой, блокировка), NAS доступен по домену | открыть `https://torrentino.example.com/`, войти, найти раздачу, поставить загрузку |
| S2 | Telegram-клиент неудобен/нет под рукой (телефон потерян, чужой компьютер) | тот же функционал в браузере |
| S3 | Нужно посмотреть, что качается, и поставить на паузу | `/downloads` с автообновлением и действиями |
| S4 | Нужно убрать раздачу из Torrserver | `/torrserver`, удаление |
| S5 | Обычная работа через Telegram | поведение бота не меняется |

S1 — главный: веб-часть не должна зависеть ни от Telegram API, ни от Telegram-идентичности.
Доступ снаружи — только через nginx (443, TLS), на котором уже висят два других
приложения; Torrentino вынесен на отдельный поддомен
`torrentino.example.com`. Старый путь `https://example.com/torrentino/`
на время миграции отдаёт редирект на поддомен.

## 4. Цели

- **G1. Полный паритет UI.** Все экраны, данные, сортировки, фильтры, пагинация и действия,
  которые есть в Telegram, доступны в вебе. Матрица — в
  [02-parity-matrix.md](02-parity-matrix.md).
- **G2. Независимость от Telegram.** Вход, сессии, ACL и рендеринг веба не используют
  Telegram API. При недоступном Telegram веб работает штатно.
- **G3. Один бинарник и прежний деплой.** `go build ./...`, `update-service.sh`,
  systemd-юнит и путь `/opt/torrentino` не меняются; статика встроена. Меняются
  конфигурация nginx (новый `server`-блок поддомена) и поле `web.base-path` в
  `settings.json` (в основном деплое `/`).
- **G4. Отсутствие дрейфа поведения.** Сортировки, фильтры, пагинация и действия для
  обоих UI берутся из одного UI-агностичного слоя, а не дублируются.
- **G5. Безопасность по умолчанию.** Обязательная аутентификация, CSRF-защита, пароли
  только в виде хешей, проверка путей удаления, отсутствие XSS через названия раздач.
  Удаление выполняется сразу, как в Telegram (без отдельного подтверждения).
- **G6. Эксплуатируемость.** Понятные ошибки в UI, health-эндпоинт, аккуратные логи,
  graceful shutdown, конфигурация в `settings.json`.

## 5. Не-цели (v1)

- **N1.** Замена Telegram. Бот остаётся основным UI; веб — параллельный.
- **N2.** Плеер/стриминг видео в браузере и встраивание Torrserver UI.
- **N3.** Управление настройками из веба (конфиг по-прежнему файл + рестарт).
- **N4.** Регистрация пользователей, восстановление пароля, OAuth/OIDC, 2FA.
- **N5.** Прямая публикация порта приложения в интернет. Снаружи — только nginx с TLS;
  `torrentino` слушает loopback (см. 08).
- **N6.** Мультитенантность и изоляция данных между пользователями: все веб-пользователи
  равноправны и видят одни и те же Transmission/Torrserver/Jackett.
- **N7.** Мобильное приложение/PWA/офлайн-режим.
- **N8.** История действий и полноценный аудит в UI (аудит — только в лог).

## 6. Пользователи и роли

| Роль | Описание | Права |
|---|---|---|
| Владелец NAS | основной пользователь | всё |
| Член семьи | отдельный веб-аккаунт | всё (в v1 ролей нет) |
| Аноним | нет сессии | только `/login`, `/healthz`, статика |

Аккаунтов может быть несколько, как нескольких ID в Telegram `users-list`: у каждого
свой логин/пароль и своя сессия, но права одинаковые. Отдельной read-only роли в v1 нет;
при необходимости добавляется полем `web.users[].read-only` (см. 10, «Будущее»).

## 7. Ограничения и допущения

- Go 1.24+ (`go.mod`: `go 1.24`, toolchain `go1.24.0`); локально проверено на Go 1.25.5.
- Только Unix: `syscall.Statfs` уже используется в футере `/downloads`.
- Один процесс: веб-сервер и бот живут в одном бинарнике и делят `common.Settings`
  и клиентов `api/*`.
- Внешние сервисы (Jackett, Transmission, Torrserver) остаются как есть; их API не
  меняются.
- Конфигурация читается один раз при старте; изменение `settings.json` требует рестарта.
- Сеть: интернет/домен, nginx на 443 (там же два других приложения), TLS терминируется
  nginx; `torrentino` слушает `127.0.0.1:8088`. Основной origin —
  `https://torrentino.example.com/` с `web.base-path: "/"`; поддомен уже
  резолвится (wildcard DNS), нужен отдельный сертификат.
- Старый путь `https://example.com/torrentino/` — только временный редирект на
  поддомен. Поддержка `web.base-path` остаётся в коде для fallback/локальной разработки,
  но в основном деплое префикса нет.
- Общий origin с двумя приложениями был риском: скрипт соседнего приложения мог читать
  наши страницы и CSRF-токены. Вынос на поддомен этот риск закрывает; если когда-то
  вернуться к пути — риск снова появится (см. 06, T15).
- Язык интерфейса — английский, как в боте; строки вынесены в шаблоны для будущей
  локализации.
- Память: состояние сессий и списков в памяти; БД нет. Рестарт = потеря сессий.
- Браузеры: актуальные Chrome/Firefox/Safari/Edge; IE не поддерживается.
- Минимум зависимостей: веб-часть — stdlib + один вендорный JS-файл (htmx).

## 8. Критерии успеха

1. Сценарий S1 выполняется: при заведомо нерабочем Telegram-токене веб полностью
   функционален (см. 09, «Учения»).
2. Матрица паритета из 02 закрыта на 100% либо каждое отступление явно описано.
3. `go vet ./...`, `go test -race ./...`, `go build ./...` — чисто; новые пакеты покрыты
   тестами.
4. Telegram-сценарий не изменился (ручной smoke + существующие тесты).
5. Удаление возможно только в аутентифицированной сессии с валидным CSRF; выполняется
   сразу, как в Telegram; для файлов на диске путь проверяется на принадлежность
   разрешённым корням.
6. Название раздачи вида `<script>alert(1)</script>` отображается как текст.
7. Все ссылки, формы, редиректы, cookie и статика работают на
   `https://torrentino.example.com/` (base-path `/`); старый путь на базовом
   домене редиректится на поддомен.

## 9. Глоссарий

| Термин | Значение |
|---|---|
| Экран (screen) | один из `/find`, `/downloads`, `/torrserver` (с учётом `web.base-path`) |
| Состояние экрана | элементы, сортировка, фильтры, страница, выбранный элемент |
| Base path | `web.base-path`, внешний префикс всех URL; в основном деплое `/`, в fallback — `/torrentino` |
| Просмотр (view) | `common/list.View`: страница/выбор/`Dispatch`, общий для двух UI |
| Действие (action) | операция над выбранным элементом: download, pause, delete и т.п. |
| Сессия | серверная запись, привязанная к cookie; хранит пользователя и экраны |
| Паритет | совпадение доступного функционала, а не пикселей и не текста сообщений |
| Destructive-действие | удаление раздачи/файлов, необратимая операция |
| Phase 0 | рефакторинг без изменения поведения, подготавливающий второй UI |
