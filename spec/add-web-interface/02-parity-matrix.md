# 02. Матрица паритета: Telegram → Web

Источник истины — текущий код: `main.go`, `common/paginator/*`, `telegram/*`, `api/*`.
Ссылки вида `telegram/search/search.go:118` даны по состоянию на коммит `75172f9`.
Паритет означает: доступна та же информация и те же операции с теми же правилами
(сортировка, фильтрация, границы страниц, доступность действий), а не совпадение вёрстки
и текста сообщений.

## 5. Сквозные различия платформ

| # | Аспект | Telegram | Web v1 |
|---|---|---|---|
| X1 | Идентичность | `users-list` из Telegram ID (`main.go:29`) | `web.users` + пароль, независимо от Telegram |
| X2 | Проверка доступа | только для `update.Message`; callback-и проверку обходят (известный дефект, AGENTS.md п. 13) | проверка на каждом запросе, включая действия |
| X3 | Состояние экрана | глобальное на процесс, один экран на префикс (AGENTS.md п. 4) | на сессию; у разных пользователей и сессий не пересекается |
| X4 | Лимиты сообщения | 4096 символов, 4 элемента, лимит документа | нет лимита сообщения; лимит на размер `.torrent` (25 МБ) |
| X5 | Доставка `.torrent` | документ в чат | HTTP-скачивание |
| X6 | Внешние ссылки | текст сообщением | `<a target="_blank" rel="noopener noreferrer">` |
| X7 | Ошибки | лог; иногда сообщение | лог + видимый баннер, request-id |
| X8 | Разметка | HTML-строка (`ParseModeHTML`) | `html/template`, автоэкранирование |
| X9 | Навигация | команды `/downloads`, `/torrserver`, иначе поиск | навигация в шапке + форма поиска |
| X10 | Автообновление | только `/downloads` | только `/downloads` (паритет) |
| X11 | Рестарт процесса | экраны пропадают | сессии и экраны пропадают, нужен повторный вход (осознанно) |
| X12 | Несколько вкладок | не применимо (один экран на префикс в процессе) | один экран на тип в сессии; вкладки одного типа делят состояние (ограничение v1) |

## 6. Крайние случаи и ожидаемое поведение

| # | Случай | Ожидание в web |
|---|---|---|
| E1 | Пустой список | шапка «the list is empty», страница 0, действия недоступны |
| E2 | Фильтр скрыл все элементы | пустой список, фильтры остаются доступными, «сбросить фильтры» |
| E3 | После автообновления список стал короче или строки переставились | страница зажимается до `lastPage`; выбор следует за элементом по стабильному ключу, если элемент исчез — снимается |
| E4 | Удалён последний элемент на странице | переход на предыдущую непустую страницу |
| E5 | Нажатие действия для устаревшего индекса | 409 + «список изменился», без паники и без действия |
| E6 | Ошибка Jackett/Transmission/Torrserver | баннер с текстом, лог; список не портится |
| E7 | `GetInfoHash` не удался | элементом можно пользоваться дальше (если есть magnet/Link), ошибка видна строкой |
| E8 | `.torrent` вернул HTML/ошибку вместо bencode | 502, файл не скачивается, в лог — статус и длина |
| E9 | Скрейпинг постера завис/упал | добавление в Torrserver всё равно выполняется, постер пустой; жёсткий таймаут 10 с |
| E10 | `Statfs` недоступен | футер без объёма диска, остальное работает |
| E11 | Файл на диске совпадает по имени с торрентом | на диске не дублируется (как в `downloads.go:242`) |
| E12 | Одинаковые имена разных торрентов | отображаются отдельно, действия привязаны к ID |
| E13 | Поиск длится дольше 60 с | таймаут Jackett, понятная ошибка, кнопка повтора |
| E14 | Клиент закрыл вкладку во время поиска | запрос отменяется по `r.Context()`, горутина не висит до 60 с |
| E15 | Сессия истекла во время действия | 401 + редирект на `/login` (с учётом base-path), действие не выполняется |
| E16 | Нет CSRF-токена/чужой Origin | 403, действие не выполняется |
| E17 | Две вкладки одновременно жмут разные действия | команды сериализуются мьютексом экрана; результат детерминирован |
| E18 | Название раздачи с HTML/JS | экранируется шаблоном; CSP запрещает inline-скрипты |

## 7. Сознательные отличия от Telegram

Это не потеря функционала, а исправление платформенных ограничений; каждое отступление
должно быть отражено в приёмке (09).

1. Страница списка — 20 элементов вместо 4 (настраивается).
2. Поиск запускается формой, а не любым сообщением: в браузере «любой текст» не имеет смысла.
3. Панель действий видна для выбранной строки всегда; сортировки/фильтры — отдельная
   раскрывающаяся панель (в Telegram они взаимоисключающие из-за нехватки места).
4. Кнопка `delete` красная и имеет `title` о необратимости (в Telegram — обычная кнопка).
5. `.torrent` скачивается браузером, а не отправляется документом.
6. Web page открывается ссылкой, а не сообщением.
7. Ошибки видны в интерфейсе, а не только в логе.
8. После автообновления опции фильтров пересобираются по фактическим статусам
   (в Telegram накапливаются значения от прошлых обновлений).
9. Автообновление приостанавливается, когда вкладка скрыта.
10. Показ номера в очереди мультисортировки (сама очередь и порядок — как в Telegram).
11. Ограничение длины поискового запроса (256 символов) и размера `q` — защита от мусора.

Отдельного подтверждения удаления нет: это **паритет** с Telegram, а не отличие.
Риск случайного клика принят; компенсируется CSRF/Origin, проверкой пути, выбором по
стабильному ключу и аудитом (см. 06, §12 и §15).

## 8. Что не переносим

- inline-клавиатуру, callback-данные и `AnswerCallbackQuery`;
- редактирование сообщений и лимиты Telegram;
- команды `/find`, `/downloads`, `/torrserver` как текстовые команды (навигация в UI);
- `ReplyDocument` и отправку файлов в чат;
- Telegram-специфичные «заглушки» кнопок (`stub`, `-`);
- глобальный реестр `paginator.Handlers` (веб не регистрирует Telegram-handler-ы).
